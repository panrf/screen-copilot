# 读屏代操作：故障排查手册

本文件汇总实战中反复出现的失败模式。遇到操作"没反应"时按顺序排查，**不要重复试同一个动作超过 2 次**。

---

## 1. 点击落在错误位置（最高频，占故障 80%）

**症状**：点击后页面毫无变化；点击 X 位置却触发了 Y 位置的功能；输入框点了没光标。

**根因**：Windows 显示缩放（125% / 150%）下，DPI-unaware 的 Python 进程看到的是**虚拟分辨率**（如 1280x800），而截图工具给出的是**物理分辨率**（1920x1200）。坐标按 1.5 倍错位。

**诊断**：
```
python scripts/screenops.py size
```
输出中 `screenshot` 与 `GetSystemMetrics` 必须相等。若不等 → DPI 未修复。

**修法**：任何用到 pyautogui 的脚本，**必须在 `import pyautogui` 之前**执行：
```python
import ctypes
ctypes.windll.shcore.SetProcessDpiAwareness(2)   # 或 user32.SetProcessDPIAware()
import pyautogui
```
`screenops.py` 已在模块顶部内置此逻辑，优先直接调用它，不要临时手写脚本。

**换算陷阱**：视觉模型读截图时可能按"缩放后的显示尺寸"报坐标（例如截图实际 1920x1200，模型按 1080 宽描述）。此时真实坐标 = 模型给的坐标 × (1920 / 1080) ≈ ×1.778。**让视觉模型直接报物理像素坐标**，或在提示词中明确要求"按图片实际像素尺寸给坐标"。

---

## 2. 中文打不进去

**症状**：`pyautogui.typewrite("中文")` 无输出或乱码。

**根因**：typewrite 只发送键码，无法输入非 ASCII 字符。

**修法**：走剪贴板 + Ctrl+V：
```
python scripts/screenops.py paste --text "中文内容" --enter
```
文本较长或含引号/换行时，先写入 UTF-8 文件再 `--file msg.txt`，避免命令行编码问题。

---

## 3. 点击输入框没有光标（contenteditable 焦点丢失）

**症状**：坐标确认无误、监听到点击事件，但输入框不聚焦，粘贴与按键全部无效。

**常见原因**：
- 点在了输入框内的**提示文字行**（如"按 Enter 键发送"，pointer-events 区域不聚焦编辑区）→ 往上挪 30~60px 点编辑区中部
- 页面存在**透明遮罩/浮层**（新手引导、AI 推荐条、未关闭的侧栏）拦截点击 → 先关侧栏（点 × ）或按 Esc
- 该网站输入框是 iframe / 需要先激活外层容器 → 先点聊天面板空白处，再点输入框

**标准处置**（按顺序，每步都要截图验收）：
1. `python scripts/screenops.py testfocus X Y` — 自动判断是否聚焦（FOCUS_OK / FOCUS_FAIL）
2. 失败 → 调整 Y 坐标（±40px）重试，最多 2 次
3. 仍失败 → 关掉可能遮挡的侧栏/浮层，重试
4. 仍失败 → **请用户在屏幕上手动点一下输入框**，然后只做键盘动作（粘贴 + 回车）。这是最可靠兜底，不要在坐标上死磕。

---

## 4. 网页输入框无法通过 UIA 定位

**症状**：pywinauto `descendants(control_type='Edit')` 只返回地址栏，找不到页面内输入框。

**原因**：Chromium 系浏览器不把网页 contenteditable 暴露为原生 Edit 控件（需开启完整 accessibility tree）。

**结论**：不要依赖 UIA 操作网页控件。UIA 只用于**按窗口标题激活窗口**（`screenops.py focus`），坐标点击仍走截图 + pyautogui。

---

## 5. 点标签页点到别的网站

**症状**：想切回目标页面，结果切到用户的其他标签（微博、行情等），干扰用户在忙的事。

**原因**：标签宽度随数量变化、标签位置漂移；用户同时在开新标签。

**修法**（优先级从高到低）：
1. **地址栏导航**（最可靠）：`focus` 目标窗口 → `hotkey ctrl l` → `paste --text "https://..." --enter`（URL 尽量纯 ASCII）
2. 先截图确认当前激活标签，再点标签（不要凭上一次的坐标）
3. 严禁在用户主窗口里点标签；对长期协作的页面，**先分离成独立窗口**（见第 6 条）

**URL 中文丢失**：往地址栏粘贴含中文的 URL 时，中文段可能被吞（只剩 `query=AI`）。对策：搜索词用纯 ASCII 关键词，或直接在页面搜索框里粘贴中文。

---

## 6. 避免干扰用户的其他工作

**做法**：把要操作的页面分离成独立浏览器窗口。

Edge/Chrome：右键该标签 → **将标签页移到 → 新建窗口**。
坐标操作：右键标签（先截图定位）→ 悬停"将标签页移到"→ 点"新建窗口"。

分离后用窗口标题（如"BOSS直聘"而非"BOSS直聘 和另外 14 个页面"）精准 `focus`，操作时不会触碰用户其余标签。

---

## 7. 滚轮滚动无效

**症状**：`pyautogui.scroll()` 调用后页面纹丝不动。

**原因**：鼠标悬停位置不在可滚动容器上（落在筛选栏、侧栏、固定头部）。

**修法**：
- 先把鼠标移到**列表卡片区域**中部（`move X Y`），再滚
- 用多次小步滚动（`scroll -10` 循环），一次大数值常被忽略
- 仍无效 → 点击列表区域获得焦点后按 `Page Down`（`key pagedown`）

---

## 8. 浏览器自动化（CDP / Playwright）被安全软件封杀

**症状**：带 `--remote-debugging-port` 启动的浏览器几分钟内被杀；CDP 握手挂死；`DevToolsActivePort` 不写入。

**判断**：连续 3 次不同方式（自带 Chromium / 系统浏览器 / 克隆配置）全部失败 → 环境有主动防御，**停止尝试**，改走"读屏 + 键鼠"路线。不要建议用户关闭安全软件。

---

## 9. 发送类动作的验收

**必查三件事**（截图确认，不要凭"应该成功了"下结论）：
1. 消息气泡是否出现在正确一侧（我方消息在右/绿）
2. 输入框是否已清空
3. 状态标记（送达 / 已读 / 失败图标）

若输入框仍有文字 → 多半是 Enter 未生效或焦点丢失：重新点输入框 → `key enter`。

---

## 10. 通用止损规则

- 同一动作失败 **2 次**即停止，换方案（换坐标 → 换命令 → 请用户手动）
- 每次动作后**必须截图验收**，不连续盲发多个动作
- 破坏性/对外动作（发送、提交、删除、付款）**必须经用户确认**
- 用户说"算了/不折腾了" → 立即停止，清理临时文件，给纯手动最短路径
