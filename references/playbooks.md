# 常见界面操作剧本

每个剧本都是「观察 → 动作 → 验收」闭环。所有坐标以 `screenops.py grab` 产出的截图为唯一依据，**不要复用上一次的坐标**。

---

## A. 发送一条消息（IM / 招聘 / 客服后台）

适用：BOSS直聘、微信、钉钉、客服工单、任何有对话框的系统。

1. **定位会话**
   - 左侧列表点目标联系人条目（返回列表前先截图，确认条目行位置）
   - 验收：聊天区标题栏出现对方姓名/公司
2. **激活输入框**
   - `testfocus X Y`（点在编辑区中部，避开"按 Enter 发送"提示行，通常要在提示行上方 30~60px）
   - FOCUS_FAIL → 见 troubleshooting 第 3 条
3. **写入内容**
   - 长文本先写文件：`paste --file msg.txt`（不加 `--enter`，先验收）
   - 验收：截图确认输入框内文字完整、无截断、无乱码
4. **发送**
   - `key enter`（多数 IM 支持 Enter 发送；不支持时找"发送"按钮点击）
   - 验收：气泡出现 + 输入框清空 + 状态标记（送达/已读）
5. **回报**：把实际发送内容原样复述给用户，不要只说"已发送"。

**人类在环**：对外发送前必须让用户看到最终文案并确认；用户授权"批量直发"后才可连续发送同类消息。

---

## B. 搜索 + 筛选 + 列表扫描

1. 地址栏导航到搜索结果页（`paste --text "<url>" --enter`），URL 参数里尽量只放 ASCII 关键词
2. 若必须中文关键词：点击页面搜索框 → `paste --text "关键词"` → `key enter`
3. 截图 → 逐卡片提取：标题、主体、价格/薪资、标签、状态
4. 需要看详情：点击卡片（先截图量准卡片位置）→ 右侧面板或新页面出现详情 → 截图解析
5. 滚动刷新列表：`scroll -10`（鼠标先移到卡片区），每次滚动后截图

**扫描输出规范**：给出「值得处理的 / 明确跳过的」两类清单，跳过要写一句理由（金额不符、方向不符、销售岗伪装成产品岗等），不要只列标题让用户自己判断。

---

## C. 填写表单

1. 截图 → 从上到下识别所有字段及必填标记
2. 逐字段：点输入框 → `paste --text`（或 `type` 处理纯数字/英文）→ 截图验收
3. 下拉框：点击 → 截图看选项 → 点目标项（不要用键盘盲选）
4. 复选框/单选框：点击后截图确认勾选状态
5. 提交前：**整页截图给用户确认**，特别是金额、日期、身份信息类字段
6. 提交后：截图确认成功提示/单号

---

## D. 表格 / 列表批量录入

1. 先录 1 行，截图验收格式正确（这一步不能省）
2. 确认 Tab 键能在字段间移动（`key tab`）
3. 录一行 = `paste --text` + `key tab` 循环
4. 每 5~10 行截图抽检一次，发现错位立即停止

---

## E. 文件选择对话框（上传/打开）

1. 触发上传按钮 → 系统文件对话框弹出
2. 不要试图点目录树；直接 `hotkey ctrl l`（或 `key F4`）调出路径输入框
3. `paste --text "C:\\完整\\路径\\文件.ext"` → `key enter`
4. 验收：对话框关闭 + 页面上出现文件名

---

## F. 分离页面到独立窗口（避免干扰用户）

1. 截图确认目标标签位置（不要凭记忆）
2. 右键标签 → 悬停"将标签页移到" → 点"新建窗口"
3. 截图确认：新窗口只有目标标签，用户主窗口标签数量不变
4. 之后用 `focus "<窗口标题关键字>"` 精准激活

---

## G. 读屏分析的提问模板

截图后交给视觉模型时，明确要求结构化输出，避免"描述一下"这种模糊问法：

```
这是 XXX 页面的截图（实际像素 1920x1200）。请：
1. 从上到下列出每个条目：名称 / 主体 / 金额或薪资 / 标签 / 状态；
2. 给出每个条目在 1920x1200 像素坐标系中的中心坐标；
3. 指出页面上任何弹窗、遮罩、加载中状态；
4. 不要推测被遮挡的内容，直接说明"被遮挡"。
```

关键：**要求按图片真实像素坐标给位置**，否则会拿到缩放后的显示坐标（差 1.5 倍）。
